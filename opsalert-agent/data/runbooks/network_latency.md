# 网络延迟故障排查手册

## 概述
本文档描述网络延迟升高时的排查步骤和解决方案。

## 常见原因

1. 网络拥塞 - 带宽耗尽
2. 网络设备故障 - 交换机、路由器问题
3. DNS 解析慢
4. 跨地域/跨可用区访问
5. TCP 重传率高
6. 应用层处理慢（容易误判为网络问题）

## 排查步骤

### 第一步：确认是否为网络问题

先排除应用层问题：
1. 检查服务器 CPU/内存/磁盘是否正常
2. 查看应用日志是否有异常
3. 确认应用线程池是否耗尽
4. 检查数据库/缓存等下游服务

如果以上都正常，再怀疑网络问题。

### 第二步：基础连通性检查

```bash
# 测试连通性
ping <目标IP> -c 10

# 测试端口连通性
telnet <目标IP> <端口>
# 或使用 nc
nc -zv <目标IP> <端口>

# 测试 DNS 解析
nslookup <域名>
dig <域名>
```

### 第三步：路径追踪

```bash
# 追踪路由路径
traceroute <目标IP>
# 或 mtr（更详细）
mtr <目标IP>

# TCP 模式的 traceroute（ICMP 可能被禁）
tcptraceroute <目标IP> <端口>
```

重点关注：
- 哪一跳开始延迟升高
- 是否有丢包
- 路径是否绕路

### 第四步：带宽检查

```bash
# 查看当前网络流量
iftop
nload
sar -n DEV 1 5

# 测试带宽
iperf3 -c <目标IP>
```

### 第五步：TCP 状态检查

```bash
# 查看 TCP 连接状态
netstat -s | grep -i retrans
ss -s

# 查看连接详情
ss -ti
```

关注指标：
- 重传率（Retrans）> 1% 说明网络质量差
- 连接数是否异常
- TIME_WAIT 数量

### 第六步：DNS 检查

```bash
# 测试 DNS 解析时间
dig <域名> +stats

# 查看 DNS 缓存
nscd -g  # 如果使用 nscd
```

## 解决方案

### 1. 带宽不足

**现象**：带宽使用率接近 100%，延迟飙升

**解决方案**：
1. 临时扩容带宽
2. 限流非核心业务流量
3. 优化传输内容（压缩、CDN）
4. 升级网络链路

### 2. 网络设备故障

**现象**：某一跳延迟突然升高，或丢包严重

**解决方案**：
1. 联系网络运营商/云厂商排查
2. 切换备用链路
3. 启用容灾方案

### 3. 跨可用区延迟高

**现象**：可用区之间延迟明显高于预期

**解决方案**：
1. 核心服务部署在同一可用区
2. 增加本地缓存，减少跨 AZ 调用
3. 异步化非关键路径调用

### 4. DNS 解析慢

**解决方案**：
1. 启用 DNS 缓存（nscd、dnsmasq）
2. 使用本地 hosts 减少解析
3. 更换更快的 DNS 服务器
4. 应用层增加 DNS 缓存

### 5. TCP 重传率高

**解决方案**：
1. 排查丢包原因
2. 调整 TCP 参数
   ```bash
   # 增大 TCP 缓冲区
   net.core.rmem_max = 16777216
   net.core.wmem_max = 16777216
   ```
3. 启用 BBR 拥塞控制（高延迟场景）

## 应急操作

### 快速恢复

1. **流量切换**
   - 将流量切到备用机房/可用区
   - 使用 DNS 切换或负载均衡器切换

2. **服务降级**
   - 关闭非核心功能
   - 减少跨机房调用

3. **增加重试和超时**
   - 合理设置超时时间
   - 增加重试机制（注意幂等性）

## 预防措施

1. 多机房/多可用区部署
2. 建立网络质量监控
3. 定期进行容灾演练
4. 合理规划服务部署位置
5. 核心服务尽量同机房部署

## 回滚方案

如果网络变更导致问题：
1. 立即回滚网络配置变更
2. 恢复原有路由策略
3. 切回原有链路
4. 分析问题原因后再尝试

## 相关告警
- 网络延迟 > 100ms（同机房）
- 丢包率 > 1%
- TCP 重传率 > 2%
- 带宽使用率 > 80%
- DNS 解析失败率升高
